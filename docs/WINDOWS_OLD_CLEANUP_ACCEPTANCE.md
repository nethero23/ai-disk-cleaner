# Windows.old cleanup repair acceptance

Date: 2026-10-24. Status: local R2 NSIS in-place/restart accepted;
subsequent source hardening is **merge-only, unreleased and not installed**.

## Scope and diagnosis

The owner reported no visible effect after selecting Windows.old and confirming
Recycle Bin cleanup. The old path sent the item through ordinary, non-elevated
recycling. Its UI counted failures in a green result without the actual item
error and could leave feedback above the viewport. No Windows.old execution
record was available; the exact historical Windows error is not established.

The owner approved a separate system-cleanup task and failure feedback, using
fixtures or mocks only. No actual Windows.old removal or elevation was approved
or executed. Later, separately approved installation replaced the program only;
configuration and personal history were not reset. See the follow-up below.

## Behavior and safeguards

- Windows.old selections open a separate irreversible confirmation; mixed
  selections leave ordinary items untouched. Cancel performs no cleanup.
- The task targets only the current system drive's root Windows.old. Wrong-drive
  and redirected fixture paths cannot enter this route. Generic recycling refuses
  both the Windows.old rule and the actual system-root target.
- After confirmation, the existing elevation flow uses Windows servicing:
  `DISM /Online /Remove-OSUninstall /NoRestart /English`. The generated script
  verifies system-drive consistency and rejects reparse points and non-directories.
- Exit 0 or 3010 is insufficient: the target must actually disappear. Remaining
  files produce failure and Windows Storage guidance, not a recursive-delete,
  ownership-change or multi-drive fallback. No automatic restart is requested.
- Ordinary failures expose item names, paths and actual errors, retain failed
  selections, clear stale success notices and bring feedback into view. Only
  confirmed successes leave the report; system success updates only its matching
  system-drive item and recalculates overview totals.
- This irreversible task does not enter the recyclable cleanup history and is
  not restorable there. It is not a durable system-cleanup audit journal.

## In-place installation follow-up

The separately approved first local NSIS update selected **Do not uninstall**
and kept the original installation path. Actual extraction and successful
completion were observed. All 371 profile files were hash-identical before first
launch, both shortcuts retained their hashes, and all 95 history records
(81 successes) loaded normally. The binary differs from the frozen raw build
only at Tauri's three-byte `UNK` to `NSS` bundle marker; a reference with only
that marker changed matches the entire installed binary hash.

That first installed retest was **not accepted**: the actual scanner returned
`C:\\Windows.old`, generated by a trailing separator in `SYSTEMDRIVE` plus the
rule's leading separator. Both frontend matching and the exact-root backend
guard omitted separator-run normalization. New real-template tests failed before
the fix (two Node failures and one Rust failure) and passed afterward. Wrong
drives, UNC paths, nested paths and parent-directory segments remain rejected.

The final revised package was rebuilt and its independent native app scanned
the actual system-rule path read-only plus one 4 KB fixture. Mixed selection
opened a Windows.old-only irreversible confirmation; Cancel retained both
selections. Repointing only that private test rule to an 8 KB fixture produced
a visible preflight refusal and preserved both fixtures and synthetic history.
No final system execution, UAC, DISM or real cleanup ran. A fresh 376-file backup
and two shortcut backups are verified.
